## 2. Stage0: OCaml Bootstrap Compiler (tgc0)

### 2.1 Purpose
The stage0 compiler is written in OCaml and serves as the **bootstrap seed**. It compiles a subset of Tangerine to OCaml, which is then compiled by the OCaml compiler to produce a native binary.

### 2.2 Module Breakdown

#### **token.ml** — Token Definitions
- 30+ token types: `DEF`, `END`, `STRUCT`, `ENUM`, `IF`, `MATCH`, etc.
- Literal tokens: `INT`, `FLOAT`, `STRING`, `CHAR`, `BOOL`
- Operators: `PLUS`, `MINUS`, `STAR`, `EQEQ`, `ARROW`, `FATARROW`

#### **lexer.ml** — Lexical Analysis


#### **parser.ml** — Parser
- **LL(1) recursive descent** for declarations
- **Pratt precedence climbing** for expressions
- Error recovery via synchronization at statement boundaries

**Grammar Summary:**
```
program     → item*
item        → fn_decl | struct_decl | enum_decl
fn_decl     → "def" IDENT "(" params? ")" ("->" type)? body "end"
struct_decl → "struct" IDENT field* "end"
enum_decl   → "enum" IDENT variant* "end"
expr        → literal | ident | call | binary | unary | if | match | ...
```

#### **ast.ml** — Abstract Syntax Tree
```ocaml
type item =
  | Function of function_decl
  | Struct of struct_decl
  | Enum of enum_decl
  | Ignored

type expr =
  | Int of int
  | Float of float
  | String of string
  | Var of string
  | Binary of string * expr * expr
  | Call of expr * expr list
  | Match of expr * match_arm list
  | (* ... *)
```

#### **sema.ml** — Semantic Analysis
- **Type inference** with type variables
- **Environment tracking**: structs, enums, functions, methods
- **Contract checking**: parameter types, return types, field access
- **Main function validation**: `def main() -> Int` or `def main() -> Unit`


#### **codegen.ml** — OCaml Code Generation
The codegen translates Tangerine AST to OCaml source code:

| Tangerine | OCaml |
|-----------|-------|
| `Int` | `int` |
| `Float` | `float` |
| `String` | `string` |
| `struct Foo { x: Int }` | `type foo = { mutable foo__x : int }` |
| `enum Option[T] { Some(T), None }` | `type 'a option = | Option_Some of 'a | Option_None` |
| `def foo(x: Int) -> Int` | `let foo (x : int) : int =` |
| `mut x` | `let x = ref ... in !x := ...` |

**Identifier Sanitization:**
- Reserved words → prefixed (`type` → `tg_type`, `match` → `tg_match`)
- Special characters → underscores (`foo::bar` → `foo__bar`)


**Pattern Matching:**

### 3.5 types.tg — Type System
**Type Representation:**
```tangerine
enum Type
  # Primitives
  Unit, Bool, Int, UInt, Float, Char, String, Never
  
  # Sized integers (FFI parity)
  I8, I16, I32, I64, U8, U16, U32, U64, F32, F64
  
  # Compound
  Named(TypeId, Vec[Type])
  Function(Vec[Type], Type)
  Tuple(Vec[Type])
  Array(Type, Int)
  Slice(Type)
  
  # References (ownership model)
  Ref(Type, Lifetime)
  RefMut(Type, Lifetime)
  Owned(Type)
  
  # Smart pointers
  Ptr(Type), PtrMut(Type), Box(Type), Rc(Type)
  
  # Trait objects
  Dyn(TypeId)
  
  # Effect types
  Effect(Vec[String], Type)
  
  # Type variables (inference)
  Var(TypeVarId)
  Param(String)
end
```

**Type Inference:**
- Hindley-Milner style with **unification**
- **Occurs check** to prevent infinite types
- **Type variable substitution** with depth-limited recursion

**Send/Sync Auto-Traits:**
- Automatic derivation based on field types
- `!Send` types: `Rc`, raw pointers
- `!Sync` types: `Cell`, `RefCell`, `UnsafeCell`

## 7. Compilation Flow Example

**Input:**
```tangerine
def add(a: Int, b: Int) -> Int
  a + b
end

def main() -> Int
  let result = add(1, 2)
  result
end
```

**Stage0 Processing:**

1. **Lexer** → Tokens: `[DEF, IDENT("add"), LPAREN, ...]`
2. **Parser** → AST: `FunctionDecl { name: "add", params: [...], body: [...] }`
3. **Sema** → Type checking: `add : (Int, Int) -> Int`
4. **Codegen** → OCaml:
```ocaml
let add (a : int) (b : int) : int =
  (a + b)

let main () : int =
  let result = (add 1 2) in
  result

let () = exit (main ())
```

5. **ocamlopt** → Native binary

## 9. Key Technical Decisions

### 9.1 Why OCaml as Bridge?
- **Pattern matching** maps naturally to AST processing
- **Strong typing** catches compiler bugs early
- **Native codegen** via `ocamlopt` produces efficient binaries
- **Available everywhere** via opam

### 9.2 Why Native Codegen?
- **No runtime dependency** on OCaml after bootstrap
- **Performance**: Direct machine code, no interpreter
- **Control**: Full control over ABI and calling conventions

### 9.3 Architecture Design
- **Separate passes**: Lexer → Parser → Type Checker → MIR → Codegen
- **MIR (Mid-level IR)**: Platform-independent optimization point
- **Pluggable backends**: x86-64, ARM64, (future: WebAssembly)
