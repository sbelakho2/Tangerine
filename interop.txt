Tangerine Interop ABI Specification (v0.1)
0. Scope and goals
0.1 Goals

Stable ABI contracts across compiler versions within an edition.

Zero-undefined-behavior boundaries for safe code.

Deterministic layouts for FFI types.

Explicit ownership transfer across boundaries.

No reliance on Rust’s unstable ABI; Rust interop is achieved through C ABI + generated shims.

0.2 Non-goals (v0.1)

Stable generic ABI across languages (generics are monomorphized).

Passing closures directly across C/Ruby boundaries without wrappers.

Unwinding exceptions across boundaries (panic strategy is abort by default).

1. ABI Families and linkage

Tangerine supports these ABI “families”:

extern "tangerine": Tangerine’s stable ABI (for Tangerine ↔ Tangerine dynamic libraries).

extern "c": C ABI for platform (SysV AMD64, Win64, etc.).

extern "ruby": MRI Ruby extension ABI (C ABI + Ruby C API conventions).

extern "rust": Defined as C ABI + Rust-generated shim, not Rust’s native ABI.

Normative rule: extern "rust" functions MUST be callable from Rust as extern "C" (or via generated shim), not extern "Rust".

2. Platform model
2.1 Supported targets (v0.1 baseline)

64-bit little-endian targets:

x86_64-unknown-linux-gnu (SysV AMD64)

x86_64-apple-darwin (SysV-like)

x86_64-pc-windows-msvc (Win64)

Others are allowed but not ABI-stable until specified.

2.2 Endianness

v0.1 mandates little-endian for stable ABI.

Big-endian targets are allowed but considered non-stable ABI in v0.1.

2.3 Alignment

Alignment rules follow the target’s C ABI alignment for primitive types.

repr(c) uses C ABI field layout rules.

3. Symbol naming, mangling, and exports
3.1 Export control

Declarations may be exported using:

@export("symbol_name")
extern "c" def foo(...)

If @export omitted:

extern "c" exports the exact identifier name (no mangling) unless conflicts require suffixing (see 3.4).

extern "tangerine" uses Tangerine mangling by default.

3.2 Tangerine mangling (extern "tangerine")

Mangled symbol format (UTF-8 then ASCII-escaped):

_TG{edition}_{pkgHash}_{modulePathLen}:{modulePath}_{nameLen}:{name}_{sigHash}

edition: e.g., 2026

pkgHash: 64-bit hex of package ID (name + version + registry source)

sigHash: 64-bit hex hash of monomorphized signature (types, calling convention, returns)

3.3 C symbol requirements

extern "c" must not mangle symbols by default.

Overloads are disallowed for extern "c" unless @export disambiguates.

3.4 Collision rule

If two exported symbols collide:

compiler error unless one uses @export("...").

4. Calling convention (functions)
4.1 Function ABI classification

Each extern function has:

calling convention: tangerine, c, ruby, rust

parameter passing class: by_value, by_ref, sret

unwind behavior: abort (v0.1 default)

4.2 extern "c" calling conventions

Uses platform’s C calling convention.

Return values follow ABI rules:

scalars in return registers

aggregates may use hidden sret pointer

4.3 extern "tangerine" calling conventions

Same as C ABI on the same platform unless otherwise specified.

Tangerine ABI may evolve but remains stable within an edition.

4.4 Variadic functions

Tangerine does not support declaring variadic Tangerine functions.

extern "c" variadics are allowed only via va_list wrapper types in stdlib.

5. Data layout and type mapping
5.1 ABI-safe type categories
5.1.1 “FFI-safe” types

Only these types may cross extern "c" / extern "rust" boundaries by value:

Integers: i8 i16 i32 i64 u8 u16 u32 u64

bool (1 byte, values 0 or 1)

Floats: f32 f64

Raw pointers: *T, *mut T, *const T

usize / isize (pointer-sized)

repr(c) structs composed only of FFI-safe fields

repr(c) enums restricted to “C-like” (see 5.4)

Everything else must cross by pointer/handle.

5.1.2 Non-FFI-safe types

These must NOT cross by value:

String, Array[T], Map[K,V], trait objects, closures, slices (unless defined as repr(c) view), non-C enums, generics without monomorphization.

5.2 Primitive type sizes (v0.1, 64-bit targets)
Tangerine	Size	Align	Notes
i8/u8	1	1	
i16/u16	2	2	
i32/u32	4	4

5.3 Struct layout: repr(c) (normative)
5.3.1 Rules

For a repr(c) struct:

Field order is declaration order.

Each field starts at the smallest offset ≥ current size aligned to its alignment.

Struct alignment is max alignment of fields.

Total size padded to a multiple of struct alignment.

5.3.2 Example
repr(c)
struct S
  a: u8
  b: u32
end

Layout:

a at 0

padding 3

b at 4

size 8, align 4

5.4 Enum layout
5.4.1 repr(c) enums (FFI-safe subset)

Only allowed forms:

C-like enums: variants with no payload.

Backing integer type explicit:

repr(c, tag=u32)
enum Color
  Red
  Green
  Blue
end

Layout: exactly u32.

5.4.2 Tagged unions across C

Payload enums must be represented as explicit repr(c) tagged unions:

repr(c)
struct OptionU64
  tag: u8     # 0=None, 1=Some
  payload: u64
end

Compiler can auto-generate via @ffi_union.

5.5 Slices and strings (FFI views)
5.5.1 Slice[T] FFI view
repr(c)
struct Slice[T]
  ptr: *const T
  len: usize
end

Rules:

Borrowed view only; does not own memory.

Valid only for the duration defined by the caller contract.

5.5.2 Str FFI view (UTF-8)
repr(c)
struct Str
  ptr: *const u8
  len: usize
end

Rules:

UTF-8 required by contract; validation optional but recommended in debug.

5.6 Handles for managed objects

For Ruby objects and other GC’d/VM objects:

repr(c)
struct Handle
  raw: *mut u8
end

Handles are opaque; only runtime functions may inspect.

6. Ownership and lifetime across the ABI
6.1 Ownership qualifiers (normative)

Every exported/imported symbol must explicitly describe transfer semantics using one of:

borrowed: callee does not take ownership; cannot store beyond call.

owned: ownership transfers to callee; callee must eventually free/drop using specified deallocator.

shared: reference-counted or VM-managed handle.

Syntax options:

Attributes (preferred for FFI):

@ffi(ownership="borrowed")
extern "c" def foo(buf: Slice[u8]) -> ...

Or typed wrappers: Owned[T], Borrowed[T].

6.2 Memory allocation domain

Any owned pointer must specify its allocator domain:

@ffi(alloc="tangerine") → freed by tg_free / Tangerine allocator

@ffi(alloc="c") → freed by free

@ffi(alloc="ruby") → managed by Ruby GC; must be a handle

If unspecified: compile error.

6.3 Destructors across boundary

For repr(c) types passed by value:

No destructor is run implicitly.

If cleanup is needed, it must be explicit via extern cleanup function.

7. Error and panic/exception boundaries
7.1 v0.1 panic strategy

Default: panic=abort.
Therefore:

No unwinding crosses any extern boundary.

7.2 Result across C ABI

For C interoperability, Tangerine standardizes an FFI Result pattern:

repr(c)
struct TgResult[T]
  ok: bool
  err_code: i32
  value: T   # valid only if ok
end

err_code=0 iff ok.

Error strings (optional) must be returned via out-parameter and allocator domain declared.

7.3 Ruby exceptions

Ruby calls may raise exceptions; Tangerine MUST translate them into Result at the boundary unless explicitly declared @ffi(throws="ruby") (which then requires immediate Ruby-level propagation wrappers).

7.4 Rust panics

Rust shim MUST be compiled with panic=abort for boundary functions OR must catch panics and translate to error codes.

8. Rust interoperability ABI (formal)
8.1 Core rule

Tangerine ↔ Rust interop is defined as:

C ABI + generated shim crate (tangerine_shim) with stable extern "C" functions.

8.2 Rust shim generation

tg bindgen rust generates:

a Rust crate exposing extern "C" symbols for Tangerine to call

and/or exposing extern "C" symbols Tangerine exports for Rust to call

8.3 Allowed Rust types at boundary

Only Rust #[repr(C)] structs/enums and primitives are allowed across.

Recommended Rust signatures:

Use raw pointers, slice views via (ptr,len), and explicit alloc/free APIs.

8.4 String conventions

Standard choice (v0.1):

Rust-to-Tangerine string view: (ptr: *const u8, len: usize) UTF-8

Owned strings: explicit tangerine_alloc_string API or caller-allocator explicit.

9. Ruby interoperability ABI (formal)
9.1 Ruby extension ABI

Tangerine Ruby extensions are shared libraries loaded by MRI.

Exported init symbol: Init_<extension_name>() (C ABI)

Ruby C API types: VALUE (opaque word-sized)

9.2 Ruby handle type in Tangerine
repr(c)
struct RubyValue
  raw: usize   # mirrors VALUE
end
9.3 GC rooting rules

Any RubyValue stored beyond the immediate call must be registered as a GC root.

Tangerine runtime provides:

ruby_gc_register(value)

ruby_gc_unregister(value)

9.4 Ruby string/array conversions

Two modes:

Copy mode (default safe): copy Ruby String bytes into Tangerine String.

Borrow mode (advanced): borrow pointer+len only if Ruby string is frozen and pinned for duration.

Borrow mode must be explicit: @ffi(ruby_borrow="true").

10. Versioning, compatibility, and validation
10.1 ABI version tags

Every compiled artifact includes:

edition

tgc_version

abi_revision (integer)

target_triple

hash(layout_rules)

extern "tangerine" dynamic linking requires exact match of (edition, abi_revision, target_triple).

10.2 ABI test suite (required)

tg abi test must validate:

size/alignment of all exported repr(c) types

symbol names and calling convention

struct/enum layout snapshots

error ABI conformance (Result structs)

allocator domain correctness

11. Required runtime exports for interop

A Tangerine runtime providing interop MUST export:

11.1 Allocation

tg_alloc(size: usize, align: usize) -> *mut u8

tg_realloc(ptr: *mut u8, new_size: usize, align: usize) -> *mut u8

tg_free(ptr: *mut u8, size: usize, align: usize) -> Unit

11.2 Error helpers (optional but recommended)

tg_last_error_code() -> i32

tg_last_error_message(out: *mut Str) -> Unit (allocator domain must be declared)

11.3 Ruby bridge (if ruby enabled)

tg_ruby_init() -> bool

tg_ruby_eval(code: Str) -> TgResult[RubyValue]

tg_ruby_gc_register(v: RubyValue) -> Unit

tg_ruby_gc_unregister(v: RubyValue) -> Unit

12. Compiler requirements (what tgc must implement)

Layout engine for repr(c) / repr(tangerine)

Export table generator + symbol mangler

ABI checker:

reject non-FFI-safe types across extern "c"/"rust"

require ownership + allocator domain annotations for owned pointers

Stub/shim generator:

C header generator (tg bindgen c)

Rust shim crate generator (tg bindgen rust)

Ruby extension scaffolding (tg bindgen ruby)

ABI snapshot tests and tg abi test
